Where to Aggregate

Liferay's Object endpoints filter, sort and paginate, but they don't group. So a chart has to group the rows somewhere. These pages walk through the four places it can happen. Every number was measured on a demo portal holding 48,048 Sales Orders.

The four rungs

Rung 1

In the browser

Fetch one page of entries, group them in JavaScript. Works on any Object, and is exact while the Object fits in one page.

1 request · sees 500 of 48,048 rows Rung 2

Filter, then aggregate

Push the filter and the field list into the Headless query, so you fetch fewer rows and fewer columns.

EMEA in June: 2,258 rows · 5 requests Rung 3

On the server

A Node Client Extension scans every page as the signed-in user and sends back only the chart's points.

97 requests · 158 bytes to the browser Rung 4

A precomputed cube

An Object Action keeps a small aggregate Object current on every write. It stores the grain, not the answer.

96 rows · read with rung 1 again
It's a loop, not a ladder The cube is just another Object, small enough for one page. So rung 4 is read with rung 1, and every question inside the grain is ad-hoc again.
