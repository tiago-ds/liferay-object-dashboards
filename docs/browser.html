Rung 1

Aggregating in the Browser

The widget fetches one page of entries from the Object's Headless endpoint and groups them with aggregate(), a pure function that knows nothing about Liferay. It works on any Object the moment it's published. It's exact as long as the Object fits in one page.

Two Objects, two outcomes

Support Case · 400 rows

Average resolution hours by priority. All 400 rows fit in one page, so the browser saw everything.
Footnote: all 400 rows. Exact, and identical to the server-side result.

Sales Order · 48,048 rows

Sum of amount by region, from the first page only.
Footnote: Showing the first 500 of 48,048 rows (<1%).

Right shape, wrong totals

The ranking from the first page happens to match the real one. The totals are off by a factor of almost a hundred. The browser was right about the rows it saw. It was wrong about how many there were.

RegionFirst page (500 rows)All 48,048 rowsShare seen

An average over the same 500 rows would land within a few percent of the truth. A sum or a count is off in proportion to the rows it never saw. That's why the widget always states its denominator.

Where it stops

Past 500 rowsSums and counts are only as complete as the one page. More pages from the browser means shipping rows just to throw them away.
Payload and memoryEvery row crosses the network and sits in the tab before it's grouped.
