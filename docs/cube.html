Sales Order Cube

An Object that stores the grain, not the answer: one row per region × category × month, holding a count and two sums. An Object Action keeps it current on every write to Sales Order, and the widget reads it with the browser strategy in a single request.

Write path and read path

Source Object Sales Order 48,048 rows · 97 requests to scan
→
Object Action On add, update, delete Function executor calls a microservice CX, which adjusts one or two cube cells
→
Cube Object Sales Order Cube 96 rows · under the 500-row page cap
→
Widget object-dashboard Browser strategy, 1 request. No widget code changes: the cube is just another Object.

Schema

ERC SALESORDERCUBE · company scope · REST path /o/c/salesordercubes. The widget's classify.ts reads these field types and offers the dimensions and measures below with no configuration.

FieldTypeRoleWhat it holds
externalReferenceCodesystemcell keyThe grain itself, e.g. APAC|Hardware|2026-01. The Action upserts with PUT …/by-external-reference-code/{erc}, so each cell exists exactly once.
regionText · StringdimensionCopied from Sales Order. 4 values.
productCategoryText · StringdimensionCopied from Sales Order. 4 values.
monthDate · Datetime dimensionFirst day of the order's month, e.g. 2026-01-01. A Date, so the widget can still bucket it by month or quarter. 6 values.
orderCountInteger · IntegermeasureOrders in the cell. Also the weight for any average.
amountSumPrecisionDecimal · BigDecimalmeasureSum of amount. Same type as the source field, so cents survive the roll-up.
quantitySumInteger · IntegermeasureSum of quantity.
amountAvgnever storedleft outAn average of averages is wrong unless every cell has the same count. Compute it at read time from amountSum and orderCount.

How the Action keeps it current

Sales Order eventCube change
AddedCell for the new order: orderCount + 1, amountSum + amount, quantitySum + quantity. Create the cell if it is new.
DeletedSame cell, the same three values subtracted.
UpdatedSubtract the old values from the old cell, add the new values to the new cell. If region, category or month changed, those are two different cells.

Two writes landing on one cell at once can lose an increment. Run the update as read-then-PUT with a retry, or rebuild the cube from scratch on a schedule as a safety net.

What the cube gives up

Dimensions not in itChannel and status are gone unless you add them on write. Adding channel makes 288 rows.
Finer grainA monthly cube cannot answer by day or week.
High cardinalityA dimension with hundreds of values multiplies the cube past one page. Rung 3 over the cube is still cheap then.
